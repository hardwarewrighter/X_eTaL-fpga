Calculator rules decided with the user 2026-10-15, before the panel: (1) negatives stay two's complement (5-7= shows FFFFFFFE); (2) = pressed twice clears to 0 (12+3== computes 15, then 0), so no Clear key and no reset button; (3) overflow: a carry out of digit 7 on + or * sets R14 and the display shows OuErFLO until the next key, which clears it and acts as after = with the result 0. Radix's specification (rx:c_alc) first, then rom/calc.asm, the Hex1000 harness (s_creen or a flag for R14), tests on every rule, docs/calc.md. Note for the panel step (its prompt predates this): the display is a MAX7219 module (SPI-style, write-only: data, clock, load; no-decode mode with our hex font; 5 V with a 74AHCT125 level shifter), not I2C.
